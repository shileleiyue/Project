## 一、项目概述

### 1.1 项目背景

暑期培训期间，教室和实验室有大量设备被学生借用（投影仪、摄像头、开发板等），传统纸质登记容易出现设备占用冲突、归还不清楚、损坏无人负责、维修进度不可追踪等问题。本系统用于管理设备借用、归还、损坏上报、维修派单和维修结果确认。

### 1.2 系统角色

| 角色 | 核心职责 |
|------|----------|
| **学生（student）** | 查看设备、申请借用、归还设备、上报损坏、查看自己的记录 |
| **管理员（admin）** | 管理设备、审核借用、确认归还、创建维修工单、分配维修人员、查看审核记录 |
| **维修人员（repairer）** | 查看分配工单、接收任务、更新维修状态、上传维修凭证 |

## 二、技术栈

### 前端
- **语言**：HTML + CSS + JavaScript (ES6+)
- **架构**：MPA 多页面架构
- **模块化**：IIFE 模块模式
- **HTTP**：Fetch API
- **样式**：CSS 变量主题系统

### 后端
- **语言**：Python 3.10+
- **框架**：FastAPI
- **ORM**：SQLAlchemy 2.0（异步）
- **数据库**：MySQL 8.0
- **认证**：JWT（python-jose）+ bcrypt 密码加密
- **测试**：pytest + pytest-asyncio + SQLite（测试用）

## 五、后端部署

### 5.1 配置数据库

1. 确保 MySQL 8.0 已安装并运行
2. 创建数据库（如已存在可跳过）：

```sql
CREATE DATABASE campus_device CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 5.2 配置环境变量

编辑文件：`D:\IST\Project\Python\campus-device\campus-device-backend\.env`

```env
# 数据库连接（请修改为实际的用户名和密码）
DATABASE_URL=mysql+asyncmy://用户名:密码@localhost:3306/campus_device

# JWT 配置
SECRET_KEY=campus-device-secret-key-2026-summer-assessment
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=1440

UPLOAD_DIR=uploads
```

## 七、角色操作指南

### 7.1 学生（普通用户）

#### 7.1.1 注册账号

1. 打开 `http://localhost:5500/register.html`
2. 填写用户名、手机号、密码
3. 选择角色为「学生」
4. 点击「注册」

#### 7.1.2 登录

1. 打开 `http://localhost:5500/login.html`
2. 输入手机号和密码
3. 点击「登录」

#### 7.1.3 浏览设备大厅

登录后进入首页，可以看到：
- **搜索栏**：按关键词搜索设备
- **类型筛选**：笔记本电脑 / 手机 / 平板 / 相机 / 投影仪 / 其他
- **状态筛选**：可借用 / 已借出 / 已损坏 / 已下架
- **设备卡片**：展示设备名称、类型、状态标签
- **分页器**：底部翻页

#### 7.1.4 申请借用设备

1. 在设备大厅点击设备卡片进入详情页
2. 点击「申请借用」按钮
3. 填写借用原因和预计归还时间
4. 提交申请，等待管理员审核

#### 7.1.5 查看借用记录

导航栏点击「我的借用」，可以查看：
- 借用状态（待审核 / 借用中 / 待归还确认 / 已归还 / 已损坏）
- 申请时间和借出时间

#### 7.1.6 归还设备

在「我的借用」页面，对状态为「借用中」的记录：
1. 点击「归还」按钮
2. 选择归还状态：
   - **正常归还**：设备完好，直接归还
   - **损坏归还**：填写损坏说明
3. 提交归还申请，等待管理员确认

管理员拥有系统最高权限，可以看到所有管理页面。

导航栏 →「设备管理」：

| 确认归还 | 学生归还后，确认归还完成，设备恢复可借用 |

## 九、设备状态流转说明

### 借用流程

```
学生申请借用 → pending（待审核）
管理员审核通过 → borrowing（借用中）
学生归还 → pending_return（待确认归还）
管理员确认 → returned（已归还），设备恢复 available
```

### 损坏归还流程

```
学生归还（损坏）→ damaged_returned（已损坏归还）
设备状态 → damaged（已损坏）
管理员创建维修工单 → pending（待处理）
管理员分配维修人员 → assigned（已分配）
维修人员接收 → repairing（维修中）
维修人员完成 → repaired（已修复）
管理员确认 → completed（已完成），设备恢复 available
```

### 状态标签颜色对照

| 状态 | 颜色 | 中文 |
|------|------|------|
| `available` | 绿色 | 可借用 |
| `pending` | 橙色 | 待审核 |
| `borrowing` | 蓝色 | 借用中 |
| `pending_return` | 黄色 | 待确认归还 |
| `returned` | 绿色 | 已归还 |
| `damaged_returned` | 红色 | 已损坏归还 |
| `damaged` | 红色 | 已损坏 |
| `assigned` | 橙色 | 已分配 |
| `repairing` | 青色 | 维修中 |
| `repaired` | 绿色 | 已修复 |
| `unfixable` | 红色 | 无法修复 |
| `completed` | 绿色 | 已完成 |
| `offline` | 灰色 | 已下架 |

## 十、常见问题

### Q1：启动后端报错 "ModuleNotFoundError"

**原因**：Python 依赖未安装。

**解决**：
```bash
D:\IST\Project\Python\campus-device\venv\Scripts\pip.exe install -r D:\IST\Project\Python\campus-device\requirements.txt
D:\IST\Project\Python\campus-device\venv\Scripts\pip.exe install cryptography
```

### Q2：启动后端报错 "cryptography package is required"

**原因**：MySQL 8.0 使用 caching_sha2_password 认证，需要 cryptography 包。

**解决**：
```bash
D:\IST\Project\Python\campus-device\venv\Scripts\pip.exe install cryptography
```

### Q3：数据库连接失败 "Access denied"

**原因**：`.env` 文件中的数据库用户名和密码不正确。

**解决**：
1. 编辑 `D:\IST\Project\Python\campus-device\campus-device-backend\.env`
2. 修改 `DATABASE_URL` 中的用户名和密码为实际 MySQL 配置
3. 确保数据库 `campus_device` 已创建

### Q4：登录后页面空白或跳回登录页

**原因**：后端未启动或 API 地址配置错误。

**解决**：
1. 确认后端已启动：访问 `http://localhost:8000/docs` 是否可访问
2. 检查 `js/config.js` 中 `API_BASE_URL` 是否为 `http://localhost:8000/api`

### Q5：页面样式错乱

**原因**：CSS 文件加载失败。

**解决**：
1. 必须使用 HTTP Server 或 Live Server 启动前端，不要直接双击 HTML 文件
2. 检查浏览器控制台是否有 404 错误

### Q6：Token 过期怎么办

Token 默认有效期 24 小时。过期后系统会自动跳转到登录页，重新登录即可。

### Q7：如何重置管理员密码

方法一：通过注册接口创建一个新的管理员账号。

方法二：直接在数据库中修改密码哈希值（需要先生成 bcrypt 哈希）。

### Q8：如何运行测试
